# 可选的三部分交互页面

原有 `case.json` 的背景 `sections`、流程 `steps` / `metrics`、示范 `demo` 协议保持不变。没有以下字段的旧包按原方式导入、渲染。

需要把背景或流程也做成完整交互页面时，可在对应部分添加 `page`：

```json
{
  "tabs": {
    "background": {
      "sections": ["保留原规范的完整段落对象与可视化 HTML"],
      "page": { "html": "demo/index.html", "view": "background", "height": 1040 }
    },
    "workflow": {
      "steps": ["保留原规范的完整步骤对象"],
      "page": { "html": "demo/index.html", "view": "workflow", "height": 1040 }
    },
    "demo": {
      "mode": "page", "html": "demo/index.html", "view": "demo"
    }
  }
}
```

以上仅说明新增字段的位置；`sections` 与 `steps` 仍应使用原规范对象，不能把示意字符串作为正式清单提交。

本地门户在切换标签时，按需将对应页面挂载到隔离 iframe。切换同一案例的标签页会保留页面状态，离开案例路由时清理所有挂载。导入器校验 `page.html` 是否存在，支持的 `view` 为 `background`、`workflow`、`demo`。

页面可读取宿主明确设置的 `window.__CASE_DEMO_VIEW__` 来选择初始部分。独立打开时不应仅根据 `parent !== window` 隐藏导航：浏览器预览窗口也可能使用 iframe。

M1 案例同时支持 `?embed=portal&section=background`、`section=workflow`、`section=demo`，并保留可独立运行的三部分导航。

旧门户若不支持 `page`，会继续读取原规范的背景段落、流程步骤和可视化图解；因此原规范内容仍需写完整。其他同学的旧包无需增加本扩展字段。
